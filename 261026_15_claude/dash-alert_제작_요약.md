# dash-alert 제작 요약

서울·경기 대중교통 경로를 조회해 출발 시각을 카카오톡 나와의 채팅으로 알려 주는 Claude Code 플러그인 제작 과정 요약이다.

## 1. 결과물

| 항목 | 내용 |
|------|------|
| 이름 | `dash-alert` (마켓플레이스 `dash-alert-marketplace`) |
| 저장소 | https://github.com/MmiInN10/dash-alert-marketplace (공개, 최신 커밋 `a1da0db`, 버전 0.3.0) |
| 목적 | 집↔회사 경로와 소요시간 계산, 첫 버스 실시간 도착으로 "뛰어라 / N분 뒤 출발 / 놓침" 판정 |
| 전달 | 터미널 출력 + 카카오톡 나와의 채팅(PlayMCP 메모챗) |
| 자동화 | 평일 06:40(집→회사), 18:00(회사→집) Windows 작업 스케줄러 |
| 문구 예시 | `[뛰어라] 9분 뒤 출발하기` / `📍 회사 [17:51 도착]` / `🚌1312번 15:57 → 🚇1호선 ~16:10 → …` |

## 2. 결정 사항

| 주제 | 결정 | 이유 |
|------|------|------|
| 구현 형태 | Claude Code 플러그인(스킬) + 파이썬 스크립트 | 카톡 전송이 PlayMCP(MCP 도구)라 Claude 세션이 필요 |
| 경로 API | ODsay 길찾기 | 장소 간 경로 제공. 공공데이터 도착정보는 한 정류장 시각만 제공 |
| 장소→좌표 | 카카오 로컬 (주소 검색 우선, 실패 시 키워드 검색) | 키워드만 쓰면 같은 건물의 가게 이름이 먼저 잡힘 |
| 버스 실시간 | PlayMCP `koreaBus-getKoreaBusArrival` | 키 발급 없이 서울·인천·경기 조회 |
| 시각 표기 | `~` 있으면 예상, 없으면 실시간 | ODsay는 "지금 기준" 경로만 제공 |
| 스케줄 | 작업 스케줄러 + `run_alert.ps1` | 로컬 설정·키를 그대로 사용 |
| 훅·에이전트 | 만들지 않음 | 현재 기능에 불필요 |

## 3. 진행 경과

| 순서 | 내용 |
|------|------|
| 1 | PlayMCP 복수 사용 가능 여부 조사 → 도구함에 여러 서버를 담는 구조로 확인, 개수 상한은 공식 자료에서 확인 못 함 |
| 2 | 고정 정류장·역 도착 조회 방식으로 1차 구현 (`arrivals.py`, `run-now` 스킬) |
| 3 | 요구 확장: 장소·도착 시각 입력 → 경로 탐색. ODsay·카카오 로컬 조합으로 `route.py`, `go` 스킬 구현 |
| 4 | 키 발급(ODsay 서버 플랫폼 + 공인 IP 등록, 카카오 REST 키) 후 실제 호출 검증 |
| 5 | 문구 양식을 `[뛰어라] N분 뒤 출발하기`로 변경, 장소 뒤 `[도착시간]`과 탑승 시각 추가 |
| 6 | 첫 버스 실시간 반영, 작업 스케줄러 2건 등록, 시험 전송 성공 |
| 7 | README 작성, GitHub 공개 저장소로 배포, 플러그인 설치 확인 |
| 8 | 코드 리뷰(박팀장 에이전트) 결과 반영 |
| 9 | 지하철 실제 시각표(국가철도공단 열차별 운행 시각표) API 신청, 승인 대기 중 |

## 4. 이슈와 조치

| 이슈 | 원인 | 조치 |
|------|------|------|
| 카카오 장소 검색 403 | 앱에서 카카오맵 서비스 미사용 설정 | 콘솔에서 카카오맵 사용 설정 |
| 도착지가 가게 이름으로 표시 | 키워드 검색이 같은 건물의 입점 업체를 먼저 반환 | 주소 검색 우선, 저장 장소는 저장 이름("회사") 표시 |
| 도착 목표 모드에서 늦은 경우 시각 오류 | 지난 출발 시각 그대로 계산 | 출발 시각을 지금으로 보정, 지각 분 표시 |
| 실패를 알 수 없음 | `claude -p`가 도구 실패에도 종료 코드 0 | 도구 호출 기록으로 성공 판정, 실패 시 카톡·윈도우 알림, 종료 코드 1 |
| 회사 실주소가 공개 저장소에 올라감 | 테스트 입력에 실제 설정값 복사 | 가짜 값으로 교체, 저장소 삭제·재생성, 기록 재작성, 작성자 이메일을 noreply로 변경 |
| 설치된 사본이 옛 버전 | 버전이 같아 갱신이 반영되지 않을 수 있음 | 플러그인 버전을 0.3.0으로 올림 |

## 5. 검증 현황

| 항목 | 결과 |
|------|------|
| 단위 테스트 | 33건 통과 |
| `-DryRun` | 실제 경로·버스 실시간 조회 확인 (카톡 전송 없음) |
| 실제 전송 | 성공 1회, 로그에 "전송 확인됨". 일부러 일으킨 실패 1회, 로그에 원인 기록 |
| 마켓플레이스 검증 | `claude plugin validate` 통과 |
| 미검증 | 윈도우 알림 경로, 스케줄러 계정 환경(`python` 탐색), 서울 지하철·공공데이터 버스 API(`arrivals.py`, `run-now`) |

## 6. 현재 한계

- 지하철 시각은 예상값이며 실제 배차 시각은 승인 후 연동 예정이다 (README 12절).
- 도착 목표 시각을 지정하면 버스 실시간 값이 반영되지 않는다.
- 공휴일을 구분하지 않고 PC가 꺼져 있으면 알림이 가지 않는다.

## 7. 해야 할 일

1. `dash-alert` 플러그인을 새 버전(0.3.0)으로 갱신하고 `/reload-plugins` 한 뒤 세션을 이어서 진행한다.
2. API 키를 입력한다 (철도 데이터 포털 승인 후 `~/.commute-alert/.env`의 `KRIC_API_KEY`).
